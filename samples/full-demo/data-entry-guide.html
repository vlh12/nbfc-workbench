NBFC full synthetic demo pack

Three reporting dates · 48 loan rows · 9 distinct NBFCs across the pack · 24 asset-quality snapshots · 7 saved-scenario recipes. All figures are fictional INR rupees; thresholds are prototype settings.

1. Start the application

In VS Code select All workbench services and press F5. Run npm.cmd run dev in frontend. Keep Oracle running. No Docker is required for this portfolio workflow.

2. Choose automatic import or manual entry

The importer uses existing local demo APIs, appends synthetic versions and records, and does not delete existing data. Default mode validates portfolios only. It requires PowerShell 7 (pwsh).

pwsh -File .Import-Demo.ps1
pwsh -File .Import-Demo.ps1 -Import

Run these from the extracted pack folder. import-state.json records created IDs for the exact portfolio, capital, quality, threshold, scenario, assessment and action versions. Re-running uses those saved IDs; keep this file with the pack. If interrupted, review the state before retrying: a failure between an API response and checkpoint write may leave an extra record. The importer is not one database transaction.

Manual alternative: Upload the three files in portfolios/ as Contributor, oldest first, validating then saving each. Supporting-data CSVs are reference tables for form entry, not portfolio uploads. Enter capital and the chosen NBFC's seven quality buckets through Contributor → Supporting data. Enter threshold settings as Supervisor. Then run scenarios as Analyst.

8. Try every analysis feature

  1. Select the newly imported September portfolio: total EAD ₹3000 crore; NBFC 001 EAD ₹1200 crore; largest share 40%; top-three share 73.33%. The doughnut has five NBFCs plus Others.
  2. Analysis desk → NBFC analysis: select SYN-NBFC-001 to see its two loans, exposure and September stress runs.
  3. View NBFC asset-quality history → Load NPA history: see July 12% → August 10% → September 7%. NBFC 002 instead deteriorates from 3% to 8%.
  4. Period comparison: prior August, current September. NBFC 001 increases ₹100 crore; 002 reduces ₹50 crore; 008 appears and 007 is absent. Absent is not evidence of closure.
  5. Scenario comparison: use September Baseline / Moderate / Severe. Severity changes 20% → 40% → 60%, while recovery, EAD, capital and input versions stay fixed. Read the risk-driver explanation.
  6. Compare threshold-comparison v1 and v2: both show 8.4% impact and ₹420 crore loss, but MEDIUM versus HIGH due to threshold versions.
  7. Compare August Severe to September Severe to see portfolio/capital/asset-quality version warnings and changed EAD. Keep their matching dates when creating each run.
  8. Heatmap: select September, NBFC 001, September capital, threshold v1. Generate 36 previews. Severity 60% / recovery 40% gives ₹432 crore loss and 8.64% impact. Cells are not saved.

9. Supervisor workflow and audit

Manual route: submit three completed scenarios as Analyst, with separate assessment notes. As Supervisor, leave one SUBMITTED, return one for correction with a reason, and approve one with a reason. Add follow-ups and move one through IN_PROGRESS → EVIDENCE_SUBMITTED (with evidence) → VERIFIED → CLOSED. The importer creates this example automatically: one pending, one returned, one approved; two overdue open/in-progress actions and one closed action, plus audit events. Counts may also include existing records.

Importer overdue dates use the India calendar date when you run it. For manual entry on 19 October 2026, use 18 October for overdue and 26 October for a future action. Decisions and actions are synthetic workflow examples, not financial recommendations.

Scope

These data cover the current portfolio, analytics, scenario and governance features. Legacy three-column exposure uploads use a different format and are intentionally separate. Failed/invalid inputs are not seeded. Record lists are capped at 100, so very large existing histories can hide older versions. The pack creates 32 input versions and 7 scenarios before governance records.
